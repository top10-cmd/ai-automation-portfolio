# LinguaDesk — Multilingual AI Support Assistant

Локальный MVP для автоматизации клиентской поддержки: обращение → анализ → черновик на языке клиента → русское резюме → проверка оператором → журнал / CRM.

**Работает без ключей и установки зависимостей.** По умолчанию включён честно обозначенный mock: правила и шаблоны, а не вызовы нейросети. Live-адаптер реализован отдельно. Все данные в примерах вымышленные.

## Бизнес-задача и ценность

Оператору приходится определять язык, тему и приоритет каждого обращения, затем писать ответ. LinguaDesk собирает эти действия в одном интерфейсе, оставляя решение за человеком. Ожидаемая польза: меньше ручной сортировки, единый порядок проверки и понятная история действий.

Экономия времени пока не измерена; процентов и обещаний результата нет. Для пилота можно сравнить время подготовки ответа, долю правок и долю неверной классификации на одинаковом наборе синтетических обращений.

## Быстрый запуск

Нужен Node.js 22.6+; проверено на Node.js 24.19.0. Откройте терминал в папке распакованного проекта:

```text
node server.mjs
```

Откройте [операторский центр](http://localhost:3000) или [каталог четырёх проектов](http://localhost:3000/portfolio.html). Установка пакетов не требуется. Остановить сервер: Ctrl+C. Для повторного запуска используется та же команда.

Файл `.env` необязателен в mock-режиме. Для настройки скопируйте `.env.example` в `.env` и заполните только нужные параметры. Настоящий `.env` не публикуется и не включается в архив.

## Что работает

- Ввод до 4000 символов, автоопределение языка и ручное уточнение.
- Независимые поля темы, срочности и тональности.
- Черновик на языке клиента и краткое русское резюме.
- Редактирование, отклонение и обязательное подтверждение оператором.
- Журнал статусов и действий с экспортом JSON, без текстов сообщений.
- Локальный сервер с API и постоянным журналом метаданных.
- Серверный OpenAI Responses-адаптер со строгой JSON Schema.
- Подтверждаемая оператором передача в CRM через HTTPS webhook, обработка ошибок и повторов.
- Подготовленный n8n-шаблон приёма обращения и эквивалентная схема полного процесса.

Mock содержит 11 языков: русский, английский, немецкий, французский, испанский, итальянский, португальский, турецкий, японский, китайский, арабский. Это словарь правил, а не универсальное понимание текста. Короткие и смешанные фразы могут определяться неверно. Для неизвестного языка черновик пустой, предлагается ручная проверка; английский не подставляется автоматически. Русское mock-резюме описывает классификацию, но не является полным переводом.

Live-адаптер принимает свободный текст, не ограничивая автоматическое определение этими 11 языками. Фактическая поддержка и качество зависят от выбранной модели; их нужно проверять отдельно.

## Демонстрационный сценарий

1. Выбрать «EN · Срочная доставка» — это синтетический запрос.
2. Запустить анализ. Проверить English, тему доставки и высокий приоритет.
3. Прочитать русское резюме, изменить английский черновик и сохранить правку.
4. Нажать «Подтвердить · демо». Статус изменится, в журнале появятся анализ, правка и подтверждение.
5. Экспортировать журнал: в нём нет исходного текста и ответа.
6. Повторить с французским возвратом или немецким техническим вопросом.

В demo статус **«Подтверждено · демо» не означает отправку клиенту**. При настроенной CRM появляется другая кнопка. HTTP 2xx от webhook означает, что CRM приняла событие, а не что клиент прочитал сообщение.

## Архитектура

```text
Браузер / n8n
      │ POST /api/analyze
      ▼
Проверка ввода → mock / live LLM → проверка структуры → черновик
                                                         │
                                           оператор: правка / отклонение
                                                         │ подтверждение
                                                         ▼
                                        demo-статус / HTTPS CRM webhook
                                                         │
                                             журнал только метаданных
```

Модель генерирует только поля анализа. У неё нет инструментов отправки, доступа к ключам CRM или возможности самостоятельно подтвердить ответ. На сервере проверяются допустимые переходы статусов и версия обращения. Повторное подтверждение завершённого обращения не отправляет его заново.

| Файл | Назначение |
| --- | --- |
| `index.html`, `styles.css`, `app.js` | Адаптивный интерфейс оператора |
| `core.js` | Mock для 11 языков, валидация, статусы и переходы |
| `server.mjs` | HTTP API, локальная сессия, лимиты и выдача публичных файлов |
| `providers.mjs` | Live LLM, JSON Schema и исходящий CRM webhook |
| `store.mjs` | Атомарное сохранение журнала метаданных |
| `mvp.test.mjs` | Автоматические проверки |
| `n8n-workflow.json` | Шаблон: webhook → анализ → ответ; без автоотправки |
| `automation-flow.json` | Машиночитаемая схема полного процесса |
| `INTEGRATIONS.md` | Контракты и настройка LLM / CRM / n8n |

Стек: Node.js, стандартный HTTP/fetch, ES modules, HTML/CSS/JavaScript, JSON Schema, webhooks. Без внешних npm-зависимостей. В каталоге четыре кейса: Support, HR, CRM Lead Assistant и AI-assisted Copywriting. HR и CRM остаются автономными mock-демо, а страница copywriting показывает синтетические текстовые примеры.

## API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Состояние режима, выдача локальной session cookie |
| `POST /api/analyze` | `{text, synthetic:true, languageHint?}` → новое обращение со статусом `review` |
| `GET /api/logs` | История метаданных |
| `GET /api/tickets/:id` | Черновик текущего запуска; после перезапуска недоступен |
| `POST /api/approve` | `{id, version, decision, reply?}`; решения: `edit`, `reject`, `approve`, `retry` |

Режим задаётся только сервером. Браузер работает через локальную HttpOnly/SameSite session cookie. Для программного клиента доступен Bearer `API_TOKEN` из окружения. Это не многопользовательская авторизация.

## Включение live LLM

В локальном `.env`:

```dotenv
LLM_MODE=live
LLM_API_KEY=your_key_here
LLM_MODEL=your_supported_model_id
```

Нужны API-ключ OpenAI, доступная модель с поддержкой Responses и Structured Outputs, доступ к API и оплачиваемый API-баланс. Перезапустить сервер после изменения окружения. Настоящие значения не вводить в браузер, workflow JSON или GitHub.

Endpoint фиксирован на OpenAI Responses; универсальный URL провайдера не используется. Ошибка, отказ или неверная структура ответа явно показываются пользователю — тихой подмены на mock нет.

Настоящий платный вызов не выполнялся: контракт проверен подставными ответами. После подключения ключа нужно отдельно проверить реальные языки, качество резюме и черновиков. JSON Schema проверяет форму, а не достоверность ответа. Синтетический текст в live передаётся внешнему провайдеру.

## CRM и n8n

Для CRM задать `CRM_WEBHOOK_URL` и при необходимости `CRM_WEBHOOK_TOKEN`. Ключ повторной доставки стабилен и равен ID обращения; получатель должен сам подавлять дубликаты. Таймаут не доказывает, что событие не дошло. Никакой автоматической отправки без подтверждения оператора.

n8n-шаблон выключен по умолчанию. Это готовая основа для настройки приёма, а не заявление о проверенной интеграции с чужой CRM. Настройка, ограничения локального подключения и контракты: [INTEGRATIONS.md](INTEGRATIONS.md).

## Данные и безопасность

- Только вымышленные обращения; явное подтверждение в интерфейсе и `synthetic:true` в API.
- Тексты, резюме и черновики не сохраняются на диск. В памяти остаются только результаты анализа текущего запуска.
- На диске: `.data/journal.json`, максимум 500 записей метаданных. До 200 активных обращений за запуск, 30 анализов в минуту, не более 3 одновременно.
- После перезапуска журнал остаётся, а текстовые результаты недоступны. Это сознательный компромисс приватности MVP, не полноценный helpdesk.
- Простая маскировка email, телефонов и типичных ключей — дополнительная защита, **не гарантия обезличивания**. Не вводить реальные ФИО, адреса, номера документов и другие персональные сведения.
- Сервер слушает только loopback; проверяет Host/Origin. Служебные файлы и `.env` не выдаются HTTP-сервером.
- Нет полноценной системы пользователей, RBAC, TLS-развёртывания, базы заявок и резервного копирования. Не выставлять этот локальный сервер в интернет без отдельной доработки.
- Журнал действий не криптографически защищён и не является compliance-аудитом.

## GitHub Pages и публикация

GitHub Pages показывает только автономный mock-интерфейс; Node.js backend там не запускается. Для новой статической версии нужны как минимум `index.html`, `app.js`, `styles.css`, `core.js`; для каталога — также страницы HR, CRM и copywriting.

На статическом хостинге метаданные сохраняются в localStorage браузера. После обновления страницы текстовые результаты пропадают, история остаётся. Открытие `index.html` двойным щелчком через file:// не поддерживается: нужен локальный сервер или статический HTTPS-хостинг.

Этот пакет подготовлен локально. Публикация новой версии не означает автоматического размещения backend. Существующий [репозиторий портфолио](https://github.com/top10-cmd/ai-automation-portfolio) и [опубликованный каталог](https://top10-cmd.github.io/ai-automation-portfolio/portfolio.html) — отдельная ранее опубликованная версия.

Стандартная команда: `npm test` (если npm доступен). Без npm, в проверенной среде Node.js 24:

```text
node --test --test-isolation=none mvp.test.mjs
```
